# 02 — 磁盘格式与编码规范

本文档记录 kvdb 实现并验证的每一项磁盘格式，全部取自本仓库
`leveldb/` 目录的官方源码（逐常量核对），保证与 LevelDB 双向兼容。

## 1. 编码原语（util.c）

### 1.1 定长编码（小端）
- `EncodeFixed32`: 4 字节 LE；`EncodeFixed64`: 8 字节 LE。

### 1.2 Varint32/64（LEBase128）
- 每字节低 7 位为数据，最高位为延续位；64 位最多 10 字节。

### 1.3 CRC32C
- 多项式 0x82F63B78（反射），初值 0xFFFFFFFF，终值异或 0xFFFFFFFF。
- **leveldb 特有语义**（关键）：
  - `Value(x) = Extend(0, x)`
  - `Extend(crc, x)`: 内部先 `crc ^= 0xFFFFFFFF`，查表后再 `^= 0xFFFFFFFF`
    ——保证 `Extend(Value(a), b) == Value(a‖b)` 且 `Value(x,0)==0`。
  - 掩码：`Mask(crc) = ((crc>>15)|(crc<<17)) + 0xa282ead8`，
    `Unmask` 为逆操作（先减 delta 再旋转回）。
  - 存盘的校验值是 `Mask(Value(type‖payload))`。

### 1.4 Hash
leveldb 的 murmur 变体：`m=0xc6a4a793, r=24`，4 字节步进，
尾部 1–3 字节逐个累加后 `h = h*m; h ^= h>>r`。bloom 用种子
`0xbc9f1d34`，缓存分片用种子 0。

## 2. 内部键（dbformat）

```
internal_key := user_key ‖ fixed64(seq<<8 | type)
type: 0=Deletion, 1=Value
seq: 56 位（kMaxSequenceNumber = 2^56 - 1）
```

内部比较器 `leveldb.InternalKeyComparator`：
1. user key 按用户比较器升序；
2. seq+type 打包值**大者在前**（新版本排在前面）；
3. `FindShortestSeparator/FindShortSuccessor` 在 user 部分缩短后拼接
   `PackSequenceAndType(kMaxSequenceNumber, kTypeValue)`。

LookupKey（搜索键）：`varint32(user_len+8) ‖ user_key ‖ fixed64(seq<<8|kTypeValue)`，
同一编码即 memtable 内条目键（`memtable_key`）。

## 3. 文件命名（filename.cc）

| 文件 | 格式 | 说明 |
|---|---|---|
| CURRENT | `MANIFEST-%06llu\n` | 经 `%06llu.dbtmp` 写入后 rename 原子替换 |
| MANIFEST-N | 日志格式 | 版本编辑记录流 |
| N.log | 日志格式 | WAL |
| N.ldb / N.sst | SSTable | 写 .ldb，读两者兼容 |
| N.dbtmp | — | CURRENT 的临时文件 |
| LOG / LOG.old | 文本 | 信息日志（打开新 LOG 前把旧的改名为 .old） |
| LOCK | — | 进程锁 |

解析规则：`MANIFEST-<数字>`、`<数字>.log/.sst/.ldb/.dbtmp`、
CURRENT/LOCK/LOG/LOG.old；数字溢出或未知后缀返回不可解析。

## 4. 日志格式（WAL 与 MANIFEST 共用，log.c）

```
块大小 32768；记录头 7 字节: crc32c(Mask,4) ‖ length(LE16) ‖ type(1)
type: 0=Zero(填充) 1=Full 2=First 3=Middle 4=Last
crc = Mask(Value(type字节 ‖ payload))
```

写入：块尾剩余 <7 字节则填零并换块；单条记录按块内可用空间分片。
读取（pos 游标实现，语义同 leveldb）：
- 头不完整且 EOF → 结束；
- `7+len > 剩余` → 未 eof 报 "bad record length" 并清缓冲重同步；
  已 eof → 静默按截断处理（writer 半路死亡）；
- type=0 且 len=0 → 跳过（坏记录）；
- CRC 不匹配 → 报 corruption、清缓冲、跳到下一块边界；
- 初偏移之前的物理记录返回 BAD_RECORD；
- First/Middle/Last 在调用方 scratch 中拼装；跨块First空记录
  （leveldb 旧 writer bug）有专门兼容逻辑。

## 5. WriteBatch（write_batch.c）

```
rep := fixed64(sequence) ‖ fixed32(count) ‖ record*
record := 0x01 var32(key) key var32(value) value     (Put)
        | 0x00 var32(key) key                        (Delete)
```

- `InsertInto`：按序分配 sequence，Put→kTypeValue，Delete→kTypeDeletion
  （value 为空）写入 memtable；结束时校验计数一致，否则 Corruption。
- `Append`：count 相加，rep[12:] 拼接。

## 6. MemTable 条目（memtable.c）

```
entry := varint32(ilen) ‖ internal_key(ilen) ‖ varint32(vlen) ‖ value
```

存于 arena，插入 skiplist（键为 entry 起始指针）。比较函数对 entry
做**无界**长度前缀解码（varint 上限 5 字节，数据体长度不受 5 字节
限制——这一点是移植期重大 bug 的根源，见 doc/04 #3）。
`Get`：seek LookupKey 后校验 user key 相同：Value→返回值，
Deletion→返回 NotFound 状态（表示"确认已删"）。

## 7. SSTable（table.c / block.c / filter_block.c）

### 7.1 块（Block）
```
entry := varint32(shared) ‖ varint32(non_shared) ‖ varint32(value_len)
       ‖ key_delta ‖ value
块尾: fixed32*restarts ‖ fixed32(num_restarts)
```
- 每 `block_restart_interval`（默认 16，index 块为 1）条重启一次
  （shared=0）。
- 迭代器：重启点二分 + 区间内线性；支持 Prev（回退到前一重启点再扫）。

### 7.2 块尾 trailer（5 字节）
```
crc32c(Mask(Value(data ‖ type字节)), 4字节) ‖ type(1字节) ‖ length(LE16)
type: 0=无压缩, 1=Snappy
```
Snappy 压缩后大小需 < 原始 - 原始/8（收益不足 12.5% 则存原始）。

### 7.3 Footer（48 字节）
```
varint64(metaindex_offset) varint64(metaindex_size)
varint64(index_offset)    varint64(index_size)
padding 到 40 字节
fixed32(magic_lo) fixed32(magic_hi)   magic = 0xdb4775248b80fb57
```

### 7.4 Table 布局
```
[data block 0] ... [data block N] [filter block] [metaindex] [index] [footer]
```
- index 条目键：块间用 InternalKeyComparator 的 FindShortestSeparator
  缩短；最后一块用 `FindShortSuccessor(last_key)`。
- metaindex：`filter.leveldb.BuiltinBloomFilter2` → filter 块句柄。
- filter 块：每 2KB（base_lg=11）数据范围一个过滤器；
  `...filters ‖ fixed32 offsets[] ‖ fixed32(offset_of_offsets) ‖ byte(base_lg)`。
- 读路径：bloom 命中判定先于 data block 读取；校验和仅在校验选项或
  paranoid 下验证；解压后的块进入 block cache（键 = cache_id‖offset）。

## 8. VersionEdit（version_edit.c）

```
tag 1: Comparator        var32(len) ‖ name     ("leveldb.BytewiseComparator")
tag 2: LogNumber         varint64
tag 3: NextFileNumber    varint64
tag 4: LastSequence      varint64
tag 5: CompactPointer    varint32(level) ‖ var32(内部键)
tag 6: DeletedFile       varint32(level) ‖ varint64(number)
tag 7: NewFile           varint32(level) ‖ varint64(number) ‖ varint64(size)
                          ‖ var32(smallest) ‖ var32(largest)
tag 9: PrevLogNumber     varint64
level 必须 < 7（kNumLevels），否则 Corruption
```

MANIFEST 语义：每次 LogAndApply 追加一条 edit；descriptor_log 为空时
先写 snapshot（comparator + compact_pointers + 全部文件）再写 edit；
超过重用阈值换新 MANIFEST 并原子更新 CURRENT。

## 9. 快照

`SnapshotList` 双向链表（head 哨兵），新快照按 sequence 递增顺序
插入尾部；`smallest_snapshot = 最老快照的 sequence`（压缩丢弃规则
A 的输入）。空链表时用 `last_sequence`。
