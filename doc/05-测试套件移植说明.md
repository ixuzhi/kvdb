# 05 — 测试套件移植说明

LevelDB 的原测试是 C++（自带 testharness + gtest 风格断言，并大量
引用内部 C++ 类）。本项目把这些**测试用例的场景与断言逐条移植为 C**，
保存在 `tests/`。本文档记录移植原则、对照清单与运行方式。

## 1. 测试基础设施

### harness（对应 util/testharness.h）
- `TEST(group, name)` 宏：GCC `__attribute__((constructor))` 自动注册
  （C 不允许非常量静态初始化，最初版本因此编译失败）。
- 断言失败通过 `longjmp` 跳出当前用例（等价于 leveldb 的 C++ 异常），
  单个用例失败不影响后续运行。
- 断言族：`CHECK / CHECK_EQ / CHECK_NE / CHECK_LT/GT/LE/GE /
  CHECK_STR_EQ / CHECK_STR_CONTAINS / CHECK_BUF_EQ（二进制安全）/
  CHECK_STATUS_OK / CHECK_STATUS_ERR`。
- `ldb_test_make_db_path`：创建测试根目录并返回数据库路径；
  `ldb_test_destroy_dir`：清空目录。

### 运行器
```
./build/kvdb_tests.exe               # 全量（92 用例）
./build/kvdb_tests.exe <子串>        # 只跑名称匹配的用例
```
注册顺序为链接序（c_api → db → log → cache → ...），与 leveldb 无关。

## 3. 移植中修正的测试级缺陷

见 `doc/04` 的 T 系列。核心教训：
1. **不要用 strcmp 比较二进制缓冲**（leveldb 用 string 断言天然安全，
   C 侧必须显式处理 NUL 结尾问题）；
2. **键存储的稳定性**：凡是被索引结构记住的指针，其背后的存储不可
   realloc/出栈（生产代码靠 arena，测试要预分配）；
3. **分片缓存的容量语义**：capacity 会被 16 个 shard 均分，小容量
   测试必须按"全局容量 ≥100"设计（leveldb 原测试也是如此）；
4. **测试宏的所有权语义**要固定（拷贝报告而非接管）。

## 4. 未移植的 leveldb 测试（及原因）

| 原测试 | 原因 |
|---|---|
| db_test 的 SpecialEnv/fault injection 部分（如 OIC corruptions、write stalls 精确计时、MANIFEST 截断恢复） | 需要故障注入 Env（可控读写失败/计数），C 侧 Env 抽象具备能力但尚未实现注入层 |
| corruption_test | 依赖对文件字节级损坏的构造工具链，属同一类 |
| autocompact_test / db_bench | 基准与压力场景，非正确性 |
| env_posix_test / env_windows_test | 平台专项 |
| c_test 的 HeapFootprint / OpenNonExistentDB 的部分细节 | 依赖 jemalloc 分配器钩子 |

这些在 `doc/06-遗留问题清单` 中列为后续工作。

## 5. 覆盖率佐证

92 个用例中，除单元层外，db 级用例在 64KB 小 write_buffer 下运行，
天然触发：memtable 切换、L0 多文件、L0→L1 压缩、平凡移动、
seek 压缩、边界文件合并、多轮 MANIFEST 滚动与 CURRENT 原子替换、
跨进程语义的文件回收——这些路径在失败测试的调试过程中均被
gdb/日志证实执行过。
